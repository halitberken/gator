# Gator

Gator is a command-line RSS feed aggregator written in Go. It lets you register users, follow RSS feeds, fetch new posts on a schedule, and browse the posts you've collected — all backed by a Postgres database.

## Features

- Register and manage multiple users
- Add and follow RSS feeds
- Periodically fetch new posts from followed feeds
- Browse collected posts from the command line
- Postgres-backed storage with schema migrations managed by [goose](https://github.com/pressly/goose)
- Type-safe database queries generated by [sqlc](https://sqlc.dev/)

## Tech stack

- [Go](https://go.dev/)
- [PostgreSQL](https://www.postgresql.org/)
- [sqlc](https://sqlc.dev/) — generates Go code from SQL queries
- [goose](https://github.com/pressly/goose) — manages database schema migrations

## Prerequisites

Before installing Gator, make sure you have the following installed on your machine:

- **Go** (1.20 or later recommended) — [installation instructions](https://go.dev/doc/install)
- **Postgres** (13 or later recommended) — [installation instructions](https://www.postgresql.org/download/)

You'll need a running Postgres instance and a database created for Gator to connect to.

## Installation

Once Go is installed, you can install the `gator` CLI directly from source using `go install`:

```bash
go install github.com/halitberken/gator@latest
```

This will download, build, and install the `gator` binary to your Go bin directory (usually `$HOME/go/bin` or `$(go env GOPATH)/bin`). Make sure that directory is on your `PATH` so you can run `gator` from anywhere:

```bash
export PATH=$PATH:$(go env GOPATH)/bin
```

You can confirm it's installed correctly by running:

```bash
gator
```

## Setting up the config file

Gator reads its configuration from a JSON file named `.gatorconfig.json` in your home directory. Create it like this:

```bash
touch ~/.gatorconfig.json
```

Then add the following contents, replacing the connection string with your own Postgres credentials:

```json
{
  "db_url": "postgres://username:password@localhost:5432/gator?sslmode=disable"
}
```

- `db_url` — the connection string Gator uses to reach your Postgres database. Update `username`, `password`, and the database name (`gator` here) to match your local setup.

Gator will update this file automatically to track which user is currently logged in as you use the CLI.

## Running database migrations

Gator's schema migrations live in `sql/schema` and are managed with [goose](https://github.com/pressly/goose). Before running Gator for the first time, install goose and apply the migrations:

```bash
go install github.com/pressly/goose/v3/cmd/goose@latest
```

Then, from the `sql/schema` directory, run:

```bash
cd sql/schema
goose postgres "postgres://username:password@localhost:5432/gator?sslmode=disable" up
```

Use the same connection string you put in `.gatorconfig.json`. This creates the tables Gator needs (users, feeds, feed follows, and posts).

## Usage

Once your config file is set up, you can start running commands with `gator <command> [args]`.

### Command reference

| Command | Description |
| --- | --- |
| `gator register <name>` | Creates a new user and logs in as them. |
| `gator login <name>` | Switches the currently logged-in user (the user must already be registered). |
| `gator users` | Lists all registered users, marking which one is currently logged in. |
| `gator addfeed <name> <url>` | Adds a new RSS feed and automatically follows it as the current user. |
| `gator feeds` | Lists all feeds that have been added, across all users. |
| `gator follow <url>` | Follows an existing feed by its URL as the current user. |
| `gator following` | Lists the feeds the current user is following. |
| `gator unfollow <url>` | Unfollows a feed as the current user. |
| `gator agg <time_between_reqs>` | Starts a long-running process that periodically fetches new posts from all followed feeds (e.g. `gator agg 1m` fetches every minute; supports durations like `30s`, `1m`, `1h`). |
| `gator browse [limit]` | Displays recent posts from feeds the current user follows. An optional `limit` argument controls how many posts are shown (defaults to a small number if omitted). |

### Example workflow

```bash
gator register alice
gator addfeed "Boot.dev Blog" https://blog.boot.dev/index.xml
gator agg 1m
```

Then, in a separate terminal, once some posts have been collected:

```bash
gator browse 5
```

This registers a user, adds a feed, starts fetching posts every minute in the background, and then browses the five most recent posts collected.

## Contributing

Contributions are welcome. If you're working on the database layer:

- Schema changes go in `sql/schema` as new [goose](https://github.com/pressly/goose) migration files.
- Queries go in `sql/queries`, written as plain SQL. Run [sqlc](https://sqlc.dev/) to regenerate the type-safe Go query code after adding or editing a query:

  ```bash
  sqlc generate
  ```

Feel free to open an issue or pull request with bug fixes, new commands, or improvements.
